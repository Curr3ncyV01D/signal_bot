## Фаза 2: Слой логики (Processor Extension)
**Цель:** Научить `BillingProcessor` принимать данные от человека, а не только от API.

1.  **`src/services/logic/billing_processor.py`**:
    *   Реализовать метод **`process_manual_approval(session, ext_id, admin_id, amount_actual) -> PaymentUpdateDTO`**.
    *   **Логика внутри:**
        1. Захват Redis-лока по `user_id`.
        2. `async with session.begin()`:
           - Загрузка инвойса и юзера (через существующий CRUD).
           - **Delta-Accounting:** Вычисление `delta = amount_actual - invoice.amount_actual`.
           - Если `delta > 0`: вызов `adjust_user_balance` и обновление `invoice.amount_actual`.
           - Смена статуса инвойса на `PAID` или `PARTIAL`.
           - Выполнение намерения (`payload`): если статус `PAID` -> покупка подписки.
           - Запись в `invoice.approved_by_admin_id`.
        3. Сборка и возврат `PaymentUpdateDTO`.

## Фаза 3: Пользовательский сценарий (Direct Manual Flow)
**Цель:** Реализовать бесшовный переход от выбора тарифа к ручной оплате по реквизитам.

1.  **Создание класса `ManualPaymentSG`(Добавь его в код файла там, где ему самое место)**:
    *   `ManualPaymentSG(StatesGroup)`:
        *   `waiting_for_screenshot`: состояние ожидания фото чека.

2.  **`src/bot/handlers/shop.py` (Рефакторинг `callback_process_purchase`)**:
    *   **Остановить**(закомментируй) вызов API Cryptomus.
    *   **Логика при нехватке баланса**:
        1. Вычислить `needed = price - user.balance`.
        2. Сформировать JSON-payload: `{"a": "sub", "d": days}`.
        3. Создать локальный инвойс в БД: `provider='MANUAL'`, `external_id='csl_manual_' + uuid`, `amount_expected=needed`.
        4. Отправить сообщение с реквизитами:
            *   Текст: Адрес холодного кошелька из `config.PAYMENT_MANUAL_WALLET`.
            *   Инструкция: "Переведите {needed} USDT и нажмите кнопку ниже, чтобы отправить скриншот".
            *   Клавиатура: Кнопка "📸 Отправить скриншот" (callback на запуск FSM) и "❌ Отмена".

3.  **Хендлеры приема доказательств (FSM)**:
    *   **Entry Point**: При нажатии "📸 Отправить скриншот" бот переводит юзера в `ManualPaymentSG.waiting_for_screenshot` и просит прислать фото.
    *   **Photo Handler**:
        1. Валидация: Если пришло не фото, а текст/документ — вежливо просим именно "Фотографию".
        2. Сохранение: Записываем `message.photo[-1].file_id` в поле `screenshot_file_id` соответствующего инвойса.
        3. Статус: Меняем статус инвойса на `WAITING_ADMIN`.
        4. Нотификация: Вызываем функцию отправки заявки в админ-чат (из Фазы 4).
        5. Ответ юзеру: "✅ Чек принят! Администратор проверит его в течение 2-х часов и автоматически начислит вам подписку. Мы пришлем уведомление".
        6. Завершение: `state.clear()`.

# Заметки

1.  **Идемпотентность:** Админ может случайно нажать кнопку дважды. Метод `process_manual_approval` должен проверять текущий статус инвойса. Если он уже `PAID`, просто вернуть текущий DTO без начислений.
2.  **Групповой контекст:** Убедись, что хендлеры админ-кнопок работают только в `ADMIN_PAYMENT_CHAT_ID`.
3.  **Безопасность фото:** Храни `file_id` оригинального изображения, чтобы не пересжимать его при пересылке.
4.  **Разделение:** Не смешивай код админских платежей с обычными админ-командами. Файл `admin_payments.py` должен быть изолирован.
