# Технический отчет: Блок 4 «Аналитика и Фильтрация»

Данный документ фиксирует изменения, превратившие систему из базового мониторинга ликвидаций в экспертный инструмент анализа рыночного давления с использованием фундаментальных данных.

---

## 1. Market Intelligence Engine (Метрики влияния)

Мы внедрили логику оценки «веса» события, что позволило пользователям фильтровать шум и фокусироваться на институциональных движениях:

*   **Cap Ratio (Global Weight)**: 
    - Внедрена интеграция с CoinGecko API для получения `circulating_supply`.
    - Реализован расчет веса ликвидации относительно рыночной капитализации монеты. 
    - Позволяет выявлять аномальные ликвидации на альткоинах (например, >0.01% всей эмиссии за 5 минут).
*   **Vol Ratio (Market Pressure)**:
    - Реализован сбор данных о суточном обороте (`turnover24h`) напрямую из WebSocket-тикеров Bybit.
    - Метрика показывает нагрузку на текущую ликвидность пары. Значения >5% сигнализируют о высоком потенциале каскадного движения.
*   **Механизм «Smart Fallback»**:
    - В [analyzer.py](file:///root/signal_bot_dev/src/services/analyzer.py) реализована логика автоматического переключения. При отсутствии данных об эмиссии (новые листинги или сбой API) система принудительно переводит триггеры конкретной монеты в USD-режим, исключая потерю сигнала.

## 2. Advanced Filtering (Управление потоком)

Расширение настроек пользователя для точечной настройки сигналов под разные торговые стратегии:

*   **Long/Short Toggles**:
    - В базу данных [models.py](file:///root/signal_bot_dev/src/database/models.py) и логику [analyzer.py](file:///root/signal_bot_dev/src/services/analyzer.py) добавлены независимые флаги `alert_longs` и `alert_shorts`.
    - Позволяет трейдерам игнорировать ликвидации противоположных тренду направлений.
*   **Двойной шлюз триггеров (Threshold Mode)**:
    - Внедрена поддержка режима `PERCENT`. Пользователь может задать порог срабатывания как в абсолютных USD, так и в процентах **Cap Ratio**.
    - Реализован «безопасный предохранитель»: даже в процентном режиме сигнал не пройдет, если он не преодолел минимальный долларовый порог (`threshold_mcap_usd_min`).

## 3. Архитектурный рефакторинг (Чистота и Скорость)

Глубокая переработка внутренней логики для минимизации задержек и устранения «хрупкости» кода:

*   **Инкапсуляция математики**: 
    - Все расчеты вынесены из Анализатора в [market_aggregator.py](file:///root/signal_bot_dev/src/services/aggregators/market_aggregator.py). 
    - Внедрено DTO `SymbolImpactMetrics`, гарантирующее типизацию данных при передаче между слоями системы.
*   **Universal Multiplier (Regex-based)**:
    - Ликвидированы жесткие проверки вида `symbol.startswith("1000")`. 
    - В [utils.py](file:///root/signal_bot_dev/src/utils.py) внедрен универсальный парсер префиксов на базе регулярных выражений. Система автоматически поддерживает любые форматы Bybit (`1000PEPE`, `1000000SHIB` и др.).
*   **Zero DB on Hot Path**:
    - Обновление кэша активных пользователей `_cached_users` вынесено в независимую фоновую задачу `user_cache_refresher_task`.
    - Анализатор больше не обращается к базе данных и не ждет `await session` в момент обработки ликвидации. Весь цикл анализа теперь на 100% выполняется в оперативной памяти (CPU-bound).

## 4. Resource & DB Optimization (Enterprise Ready)

Повышение эффективности работы инфраструктуры:

*   **PostgreSQL Bulk Upsert**:
    - В [supply_worker.py](file:///root/signal_bot_dev/src/services/supply_worker.py) реализована пакетная запись данных об эмиссии через `on_conflict_do_update`. 
    - Вместо 250 последовательных запросов выполняется один атомарный запрос, что снизило нагрузку на БД при синхронизации на 98%.
*   **Memory GC (Garbage Collector)**:
    - В агрегаторы добавлена логика автоматической очистки памяти от «мертвых» тикеров. Если данные по монете не обновлялись более 2 часов, она полностью вычищается из всех коллекций RAM, предотвращая OOM (Out of Memory).
*   **Zero-Division Protection**:
    - Введен жесткий контроль знаменателей во всех формулах. Система устойчива к «нулевым» листингам и аномалиям в API биржи.
