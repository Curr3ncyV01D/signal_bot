# 🐝 Архитектура системы «Улей» (The Hive)

Система разделена на независимые микросервисы, которые общаются через шину данных **Redis Streams**. Это устраняет блокировки Event Loop и позволяет масштабировать отправку сигналов.

## 🏗 Список сервисов (Контейнеров)

| Сервис        | Роль        | Тех. стек           | Взаимодействие                                                                          |
| :------------ | :---------- | :------------------ | :-------------------------------------------------------------------------------------- |
| **db**        | Хранилище   | PostgreSQL          | Хранит юзеров, настройки и историю ликвидаций.                                          |
| **redis**     | Шина данных | Redis 7.2           | «Нервная система». Передает сигналы между сервисами.                                    |
| **brain**     | Аналитик    | aiogram / WebSocket | **Глаза системы.** Держит сокеты Bybit, считает RSI/CVD, обрабатывает команды `/start`. |
| **artist**    | Художник    | mplfinance / pandas | **Тяжелый цех.** Рисует графики. Не имеет прямого доступа к сокетам.                    |
| **messenger** | Курьер      | aiogram             | **Доставка.** Рассылает готовые алерты пользователям.                                   |

## 🔄 Жизненный цикл сигнала (Data Flow)

1. **Захват:** `brain` ловит ликвидацию через WebSocket -> формирует JSON -> пишет в поток `csl:signals:raw`.
2. **Визуализация:** `artist` читает из `raw` -> рисует PNG -> отправляет в лог-канал (harvesting file\_id) -> пишет в поток `csl:signals:ready`.
3. **Рассылка:** `messenger` читает из `ready` -> проверяет фильтры юзеров в памяти -> отправляет алерты по `file_id`.

## ⚙️ Управление и Масштабирование

- **Если тормозят графики:** Запустить еще один инстанс `artist`.
- **Если Telegram дает FloodWait:** Запустить 2-3 инстанса `messenger`.
- **Обновление настроек:** Если юзер поменял порог в `messenger`, он кидает сигнал в Redis Pub/Sub `csl:cache_invalidation`, и `brain` мгновенно обновляет свой кэш.
