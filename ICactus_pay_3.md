# План уборки и стабилизации: CactusPay Integration

## Цель: 
Исключить самопроизвольное заполнение полей `amount_actual_native` и `amount_actual` в БД до момента реального подтверждения платежа. Обеспечить 100% точность начисления USDT.

---

## 1. Слой API: Рефакторинг клиента (`src/services/cactus_client.py`)
**Задача:** Упростить получение данных и сделать Mock-режим «честным зеркалом» базы данных.

*   **Метод `get_status`**: 
    *   Оставить чистый маппинг полей из ответа API (`total_amount`, `status`).
    *   Не добавлять в этот слой логику «если статус WAIT, то сумма 0» — это ответственность Процессора.
*   **Метод `_mock_get_status` (Критично)**:
    *   **Удалить** любую логику, которая сама подставляет `resolved_status = "ACCEPT"`.
    *   **Новая логика:** Mock должен просто читать `amount_actual_native` из инвойса в БД. 
    *   Если `amount_actual_native == 0` -> возвращать `status="WAIT"`, `total_amount=0`.
    *   Если `amount_actual_native > 0` -> возвращать `status="ACCEPT"`, `total_amount=invoice.amount_actual_native`.

## 2. Слой логики: Очистка Процессора (`src/services/logic/billing_processor.py`)
**Задача:** Внедрить «Строгий фильтр» для рублевых транзакций.

*   **Метод `_get_provider_payment_snapshot`**:
    *   Для провайдера `CACTUS` применить правило: **Статус — первичный источник истины.**
    *   Если `response.status.upper() != "ACCEPT"`, метод **обязан** вернуть `actual_native = 0.0` и `credited_amount_usdt = 0.0`.
    *   Только при `ACCEPT` мы разрешаем данным из `total_amount` и `payload["u"]` попасть в систему.
*   **Метод `process_payment_update`**:
    *   Удалить «костыли», которые пытались масштабировать рублевую сумму при частичных оплатах. Для карт это не актуально.
    *   Убедиться, что запись в `amount_actual_native` происходит только в момент фиксации успеха.

## 3. Слой данных: Фиксация Намерений (`src/database/crud/billing_service.py`)
**Задача:** Гарантировать, что при создании счета в базе всегда нули.

*   **Метод `create_invoice`**:
    *   Убедиться, что `amount_actual` и `amount_actual_native` по умолчанию всегда `0.0`.
*   **Метод `update_invoice_record`**:
    *   Оставить возможность атомарного обновления обоих полей (`actual` и `actual_native`) за один вызов, когда Процессор даст команду.

## 4. Слой UI: Синхронизация текстов и таймеров (`src/bot/handlers/shop.py`)
**Задача:** Устранить противоречия в интерфейсе.

*   **Синхронизация TTL**: 
    *   В `config.py` значение `CACTUS_INVOICE_LIFETIME_SEC` (например, 480 секунд — 8 минут).
    *   В `shop.ftl` текст в ключе `shop-cactus-pay-hosted-screen` должен автоматически вычислять минуты: `⏳ Ссылка действительна: { $minutes } мин.`. Уйти от захардкоженного текста «15 минут».
*   **Feedback**: 
    *   Если юзер нажал «Проверить», а статус `WAIT`, бот должен выдавать четкий ответ: *«⏳ Оплата еще не подтверждена платежной системой. Попробуйте нажать кнопку через 1–2 минуты»*.
